# ADR-02: Технологический стек

**Дата:** 26 октября 2026 г.

**Статус:** На рассмотрении

## Контекст

Нужен веб-интерфейс для компьютеров и телефонов без отдельных мобильных приложений (LIM01, PLT01-PLT03). Команда должна поддерживать клиентскую часть и сервисы без большого количества разных технологий.

## Рассмотренные варианты

1. React и TypeScript на фронтенде, а для сервисов выбрать C# или Go.
2. Vue и JavaScript на фронтенде, Python на бэкенде.
3. Angular и Java на бэкенде.

## Решение

- **Фронтенд:** React + TypeScript.
- **Бэкенд:** C# или Go.
- **Шина событий:** RabbitMQ, сообщения в XML по AMQP с TLS.

React отвечает за адаптивный веб-интерфейс. Каждый сервис можно написать на C# или Go на усмотрение разработчика. Перед началом разработки команда общим голосованием определяет язык для конкретного сервиса.

## Обоснование

React и TypeScript подходят для единого веб-клиента. Возможность использовать C# или Go позволяет выбрать язык под задачу и опыт разработчика, не меняя общий API сервисов.

C# подходит для сервисов, где требуется развитая бизнес-логика, большое количество библиотек и быстрый отклик API. ASP.NET Core поддерживает асинхронную обработку запросов и может использоваться для реализации основных операций системы.

Go подходит для интеграционных и фоновых сервисов. Он быстро запускается, потребляет мало ресурсов и удобен для параллельной обработки обмена с POS, CRM и другими системами.

## Последствия

- Язык каждого сервиса фиксируется в решении команды перед его разработкой.
- Для API и сообщений RabbitMQ нужно заранее описать общий формат XML, чтобы сервисы на C# и Go взаимодействовали одинаково.
- Отдельные мобильные приложения не создаются.
- Все сервисы собираются и проверяются одной процедурой перед выпуском.

## Проверка

Сборка должна проходить для React/TypeScript и выбранных C# или Go-сервисов. Интерфейс проверяется в Chrome и Safari на компьютере и телефоне.
