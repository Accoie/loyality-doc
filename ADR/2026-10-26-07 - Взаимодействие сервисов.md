# ADR-07: Взаимодействие сервисов

**Дата:** 26 октября 2026 г.

**Статус:** На рассмотрении

## Контекст

Сервисы регистрации и доступа, бонусов, акций, аналитики, интеграций и уведомлений должны обмениваться данными. Несколько POS передают покупки и возвраты; эти события нужны разным сервисам.

## Рассмотренные варианты

1. HTTP API с XML.
2. Общая шина событий RabbitMQ с XML.
3. Обмен файлами вручную.

## Решение

Использовать RabbitMQ вместо прямых HTTP-вызовов между сервисами. Протокол - AMQP с TLS (AMQPS), формат сообщений - XML. Для каждого типа сообщения описываются отправитель, получатели, поля и результат. У каждого подписчика своя очередь.

Веб-приложение обращается к сервисам по HTTPS/XML; POS и CRM - к интеграционному сервису по HTTPS/XML. Доставка сообщений внешним провайдером также использует HTTPS/XML. RabbitMQ отвечает за внутренний обмен.

## Обоснование

Одна шина RabbitMQ позволяет нескольким сервисам получать нужные события без прямых HTTP-зависимостей друг от друга. Общий формат XML позволяет сервисам работать на разных языках.

## Последствия

- Изменения форматов сообщений нужно согласовывать между сервисами.
- Для каждого сообщения нужен `message_id`; получатели отслеживают повторы.
- Внешние POS и CRM не должны напрямую обращаться к таблицам PostgreSQL.

## Проверка

Интеграционный тест отправляет покупку из каждого POS через интеграционный сервис и RabbitMQ в сервис бонусов. Проверяются получение результата, обновление аналитики, отсутствие дублей при повторе и перенос необработанного сообщения в очередь ошибок.
