# ADR-07: Взаимодействие сервисов

**Дата:** 26 октября 2026 г.

**Статус:** На рассмотрении

## Контекст

Основной, интеграционный сервис и сервис уведомлений должны обмениваться данными. Для небольшой команды нужен простой способ взаимодействия без сложной инфраструктуры.

## Рассмотренные варианты

1. HTTP API с JSON.
2. Сложная брокерная система сообщений.
3. Обмен файлами вручную.

## Решение

Использовать HTTP API и JSON. Для каждого метода описываются адрес, входные поля, результат и ошибка. Временный сбой повторяется до трех раз, после чего ошибка записывается для повторной обработки.

## Обоснование

HTTP API понятен разработчикам C#, Go и TypeScript и не требует отдельной сложной системы. Общий формат JSON позволяет сервисам работать на разных языках.

## Последствия

- Изменения API нужно согласовывать между сервисами.
- Для каждой операции нужен идентификатор запроса.
- Внешние POS и CRM не должны напрямую обращаться к таблицам PostgreSQL.

## Проверка

Интеграционный тест отправляет покупку из POS в основной сервис и проверяет получение результата и корректное сообщение об ошибке.
