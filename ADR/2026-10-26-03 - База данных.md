# ADR-03: PostgreSQL и Redis

**Дата:** 26 октября 2026 г.

**Статус:** На рассмотрении

## Контекст

Система хранит клиентов, роли, покупки, возвраты, бонусные операции, акции и аудит. Эти данные нельзя терять. Одновременно нужно быстро показывать баланс и часто используемые данные.

## Рассмотренные варианты

1. Только PostgreSQL.
2. PostgreSQL для постоянных данных и Redis для временных быстрых данных.
3. Только MongoDB и Redis.

## Решение

Использовать две базы с разными задачами:

- **PostgreSQL** - основная база и единственный источник истины. В ней хранятся все данные, влияющие на баланс и отчеты.
- **Redis** - кэш, временные сессии и короткие очереди задач. Потеря данных Redis не должна менять бонусный баланс.

## Обоснование

PostgreSQL обеспечивает транзакции и целостность данных. Redis ускоряет повторное чтение баланса и не перегружает PostgreSQL. Разделение задач остается понятным: важные данные - в PostgreSQL, временные - в Redis.

## Последствия

- При недоступности Redis система должна продолжать работу через PostgreSQL, возможно медленнее.
- В Redis нельзя хранить единственную копию покупки или бонусной операции.

## Проверка

Тесты должны подтверждать, что удаление кэша Redis не меняет данные клиента, а восстановление PostgreSQL возвращает все операции и балансы.
